# SimStudio 代理模型辅助设计：完整实施方案

日期：2026-09-23

状态：实施设计，尚未实现下述新增功能。本次已核查本地代码、发行与测试约束，并对项目环境做 CAD、采样和 GPR 组件冒烟检查；未运行 ANSYS、未训练工程代理模型、未修改项目源码。

## 1. 交付目标

完成一个可重复运行的结构设计工作流：工程目标与参数范围 → 参数化几何 → 样本计划 → 真实 Mechanical 仿真 → 数值质量检查 → 数据集 → 代理模型训练和独立评估 → 约束优化与补充采样 → 候选设计真实复算 → 设计比较报告。

首个完整案例为同一拓扑的一体式开孔结构支架。保持线弹性、小变形、单实体边界，变化板厚、开孔尺寸与圆角半径。目标为质量最小，约束为指定位置的位移和有明确评估依据的应力。质量由体积和经核对的密度计算。所有参数、材料、载荷、约束及容差需明确记录来源。

交付包括可安装的代码、严格配置与 Schema、参数化示例、CLI、独立编排 Skill、离线测试、Windows 验收入口、版本化数据与模型、优化结果及报告。工程交付还包括真实数据训练和候选设计复算证据。

## 2. 与当前项目的关系

复用现有 ansys_skill 的规范校验、单位换算、编译器、Mechanical backend、DPF 后处理和单次报告。新增 study 编排层组织这些能力；surrogate 模块只负责训练与预测，optimization 模块组织搜索与复算。

保留 simulation.yaml 的单次仿真语义，新增独立版本化 study 规格。参数边界、采样、预算、优化目标和模型设置属于 study；求解器设置仍由单次规格和显式执行配置描述。

现有目录不得直接作为任意缓存。单次运行继续要求新目录；study 使用样本 ID 和 attempt 编号管理复用与重试。现有 JSON 键、退出码及默认 dry-run 行为保持兼容，新增命令具有自己的明确契约。

建议代码职责：

| 模块 | 责任 |
| --- | --- |
| ansys_skill.study.schema | study 规格、单位、参数依赖、预算和目标校验 |
| ansys_skill.study.geometry | 受控参数化 CAD 生成器与几何合法性检查 |
| ansys_skill.study.sampling | 采样、固定随机种子、训练与测试点分组 |
| ansys_skill.study.runner | 单次运行调用、进度、串行执行、锁与中断恢复 |
| ansys_skill.study.manifest | study、样本、尝试、文件哈希和状态追踪 |
| ansys_skill.study.dataset | 数据提取、质量规则、单位统一、去重和数据集版本 |
| ansys_skill.surrogate | 响应面、GPR、评估、预测、模型保存和适用范围 |
| ansys_skill.optimization | 约束搜索、候选筛选、主动补样和复算 |
| ansys_skill.reporting | study HTML / Markdown 报告与证据关联 |

按责任组织模块，实施时可在复杂度允许的情况下合并小模块。优先保持现有包布局，避免为了扩展流程额外迁移整个 Python 工程。

## 3. study 规格必须表达的内容

| 配置部分 | 必须记录的内容 |
| --- | --- |
| 身份 | Schema 版本、研究名称、设计族、基准设计、基础仿真规格 |
| 几何 | 受控生成器名称及版本、固定尺寸、变量上下限与单位、最小壁厚等可制造性约束 |
| 物理 | 材料及属性来源、安装方式、载荷、位移测量范围、应力评估范围 |
| 目标 | 最小化质量；位移上限、许用应力及其来源；所需的数值质量条件 |
| 采样 | 方法、随机种子、初始样本、独立测试点、训练折分组 |
| 网格 | 网格策略、加密序列、代表性设计点、收敛容差、资源限制 |
| 模型 | 候选模型、允许输入和输出、训练设置、误差与适用范围判据 |
| 优化 | 参数边界、约束、候选数量、补样准则、停止条件 |
| 执行 | 明确 backend、总调用预算、重试预算、超时、串行执行配置 |
| 报告 | 需要展示的指标、证据、图像和比较基准 |

几何生成器从受审查的代码注册表中选择。配置只包含数据，不接受 Python、动态导入或待执行表达式。质量和应力准入标准不会从自然语言自动猜出一个数值后标记为已确认。

材料的密度需与实际使用的 Mechanical 材料一致。若计算安全系数，必须提供并记录屈服强度及来源；不能从材料名称推断数值。工程约束失效与数值计算失败分别记录。

## 4. 参数化几何与模型一致性

1. 为开孔支架实现一个受控 CAD 生成器，导出 STEP、参数记录、体积和几何摘要。
2. 检查单实体、非零体积、最小壁厚、孔与外边界距离、圆角可构造性及参数间约束。
3. 固定几何族与安装/加载定义。导入后核验实体名称、支承面与载荷面的唯一性、位置和面积；面编号变化不能静默改变边界条件。
4. 为变化的几何重新生成单次 simulation.yaml，并走现有 validate / compile 流程。
5. 明确应力评估区域及其选择规则，覆盖孔边和圆角等真实热点。若排除理想边界导致的奇异位置，记录工程理由，同时保留全局应力结果。
6. 对基准与参数边界附近的代表性设计做网格加密检查。每个新样本还要检查几何特征与网格尺寸是否适配；代表点收敛不等于所有样本自动收敛。

优先复用已有全局网格接口。若支架案例确实需要局部加密或更丰富的区域选择，再增加受控声明式配置，并将 Mechanical 接口适配集中在 MechanicalCompat 内，补齐官方 API 对照与实机测试。

## 5. 批量执行、恢复与跨机器运行

study 先生成全部设计点、工作量估计和可检查的执行计划。默认只做计划与离线检查，真实求解始终通过显式执行入口启动。

每个设计点维护独立状态，如 PLANNED、GEOMETRY_READY、RUNNING、SOLVED、COLLECTED、FAILED；这些执行状态与数值质量、设计约束状态相互独立。名称在实现阶段固定为稳定契约。

每次求解写入新的 attempt 目录。中断恢复时检查输入、生成器、编译器、网格/物理设置、求解环境和结果完整性；只有匹配且产物完整的记录可复用。不能仅凭目录存在或状态写着 SOLVED 就跳过。

实现 study 级单写入锁、原子状态写入、超时、有限重试、失败保留和恢复。只管理本次工作流启动的进程。日志写 stderr，机器输出写 stdout，延续当前 CLI 约定。

Windows 首版使用已记录的 mechanical_batch 路径串行运行。生成可移交的任务包，在目标机器解析相对输入路径并做环境检查；结果回收时检查 study ID、样本 ID、规格/几何及结果哈希。任务包应能脱离当前 Mac 的绝对路径运行。

软件开发阶段无需建立新的远程求解器服务。真实验收前检查 Windows 安装、许可条件和任务预算；已有历史 batch 成功记录不能代替本次验收。

## 6. 数据集与质量准入

每条数据至少关联：设计族、参数值和单位、几何/规格哈希、run 与 attempt ID、网格尺寸及数量、材料/载荷/约束摘要、求解器和提取器版本、目标值、数值检查结果、设计约束结果、运行耗时和结果来源。

数据集同时保存样本表、排除清单、检查原因、划分清单与版本哈希。为每个预测目标分别制定准入规则，不以 overall PASS / WARN 一个字段代替全部判断。

- 正式工程训练仅接受来源明确的真实求解结果。DRY_RUN、fake、缺失值、非有限值以及未完成的求解不能混入。
- 相关必要检查 FAIL 或未知时阻止该目标进入正式数据集。WARN 依据具体原因和复核证据处理；无关检查不应机械地排除所有标量。
- 位移超限但数值计算可信的设计可保留为有效、不满足约束的样本。模型假设失效的结果不能继续当作可信物理响应。
- 同一设计的不同网格和重复求解保持同组，防止进入训练与测试两侧。不同材料、载荷定义或几何族默认分开管理。
- 更换求解设置、目标统计方法或标签质量标准需生成新版本，并明确旧模型是否仍适用。

## 7. 模型训练、独立评估与预测

首版比较二次响应面与 GPR。采用明确单位和固定特征顺序，对各预测目标训练模型；质量继续由 CAD 和密度直接计算。预处理和调参只使用训练数据，交叉验证按设计点分组。

最终测试集在训练和优化之前冻结，不参与选模型、主动补样或停止规则。若后续将某些测试点用于改进模型，应重新定义独立测试集并保存新的评估版本。

评估同时报告带单位的 MAE / RMSE、最大误差、适当的归一化误差、边界区域误差、约束误判以及预测区间表现。接近零的量使用明确的绝对误差或参考尺度，不以不稳定的百分比误差掩盖问题。R² 仅作为补充指标。

模型卡保存训练数据版本、设计族、物理条件、特征和单位、训练范围、模型参数、预处理、代码与依赖版本、独立测试结果和未完成的检查。

预测返回数值、单位、模型版本和可信使用条件。检查参数上下限、参数组合、采样覆盖及模型不确定性；仅在上下限内并不足以证明可靠。证据不足时输出需要真实求解的状态，不因 predict 请求自动启动 Mechanical。

## 8. 约束优化、补样与最终复算

在明确的制造约束、参数边界和物理条件下最小化质量。代理模型用于快速预测位移和应力；搜索过程保留候选方案、预测值和约束余量，并检查几何可构造性。

GPR 不确定性可以参与候选排序和保守筛选，但需要用适当的数据检验，不能直接把若干倍标准差当作已证明的安全概率。

主动补样兼顾潜在优解、约束边界和覆盖不足的区域。每轮只提交有限数量的设计点，使用真实结果更新模型和版本记录。去重以规范化设计和物理配置为基础。

停止条件包含总求解预算、剩余时间、改进幅度、数据质量与模型误差。预算耗尽时按实际状态结束，不能自动抬高容差或宣告通过。

候选设计真实复算包含与预测独立核对的数值提取和网格检查。最终报告中的推荐方案必须有对应的真实结果与约束判断；其余仅标记为预测候选。所有结果均受本案例的线弹性、小变形与边界条件假设限制。

## 9. 公平比较与计算预算

分别记录几何生成、网格、求解、后处理、训练、预测、优化和复算耗时。比较时包含数据生成、网格检查、重试、测试点和最终验证成本。

设计求解预算时统计全部真实调用：基准 + 网格研究 + 初始样本 + 独立测试 + 主动补样 + 候选复算 + 重试。被正确复用的既有结果不重复计作新求解。

先安排 10–20 个设计点进行稳定性与耗时试运行，再根据覆盖、学习曲线和预算确定正式样本量；这只是实施中的试运行阶段，完整交付仍包括后续训练、优化和验证。无法提前保证固定样本数能达到指定误差。

对照方式至少包括基准设计与同等真实求解预算的直接采样搜索。记录最好可行设计、约束余量、真实调用数及总耗时，避免只用预测耗时宣传总流程加速。所有比较结果都需实测。

## 10. 计划新增的用户入口

以下为拟新增命令族，当前不可作为已经实现的命令运行：

| 入口 | 用途 |
| --- | --- |
| ansys-sim study init / validate / plan | 创建案例、核查完整配置、生成可审查计划 |
| ansys-sim study run / status | 批量执行、查询进度；真实求解要求 --execute，恢复使用 --resume |
| ansys-sim study export / import | 移交 Windows 任务包与核验回收结果 |
| ansys-sim study collect | 汇总数据、准入判断、冻结数据集与划分 |
| ansys-sim surrogate train / evaluate / predict | 训练、独立评估、受适用范围约束的预测 |
| ansys-sim study optimize / verify | 搜索与补样、候选真实复算；涉及求解要求显式执行及预算 |
| ansys-sim study report | 从保存的证据重新生成报告 |

阶段命令支持调试和恢复；完整工作流入口串联各阶段，在检查不满足或预算用完时给出明确结果。一次明确执行的预算可覆盖计划内的初始样本、补样及复算，不要求每个设计点重复确认。

新增一个独立的设计研究 Skill 组织上述流程，复用已有 Mechanical Skill 的工程规范。Skill 负责整理目标与缺失信息、展示计划和解释报告；确定性代码负责几何、采样、数值校验、训练和优化。

## 12. 测试、打包与文档

离线测试覆盖参数约束、单位、几何拓扑和体积、作用范围规则、确定性样本计划、目标提取、数据准入、划分隔离、预测恢复一致性、超范围处理、优化预算、中断恢复、陈旧结果失效和报告追溯。

优化算法可用具有已知解的解析函数做测试，仿真流程用明确标记的测试夹具验证。这些测试不作为工程训练或真实验收证据。普通测试不得依赖 ANSYS、许可证或网络。

新增真实测试使用 ansys_integration 标记和 ANSYS_AVAILABLE=1 显式启用；保持 Windows 串行。实机验收验证 STEP 导入、材料与作用面、不同参数设计、网格研究、恢复、DPF 标签及最终候选复算。未运行部分保持 NOT_RUN。

按仓库要求先运行最相关测试，再运行 ruff check . 和 pytest -q；检查 wheel / sdist、安装后命令、可选依赖、插件 Skill 发现及 Windows/Linux 离线 CI。保留旧命令和旧示例的回归检查。

更新中英文 README、独立 Skill、配置参考、数据与模型说明、Windows 执行/恢复指南、示例与正式验收报告。新增 Mechanical API 的签名和验证版本记入 official-api-map；源文件改变后通过正常流程生成产物。

软件功能完成与工程案例验证完成分别报告。没有真实数据、独立误差评估和候选真实复算时，不能把整套工程流程标记为已经验收。

## 14. 所需条件与本次核查

本机项目虚拟环境为 Python 3.13.12，已实际导入 CAD、SciPy 与 scikit-learn，并完成一个立方体生成、四点三维 LHS 采样和 GPR 对象构造。该检查只证明基础组件可运行，不证明完整新流程或 Mechanical 可用。

真实验收需要可访问的 Windows Mechanical 环境、对应 Python / PyMechanical / DPF 客户端、可用许可条件与明确的运行预算。历史记录使用 mechanical_batch；目标机器当前状态须在执行前重新核验。

演示案例可以由项目内自建中性几何和明确标注的示例条件提供。真实设计的载荷、位移限制、许用应力、材料依据和制造约束需有来源。工期与正式数据规模在首批试运行后按实际求解耗时和误差变化估算。
